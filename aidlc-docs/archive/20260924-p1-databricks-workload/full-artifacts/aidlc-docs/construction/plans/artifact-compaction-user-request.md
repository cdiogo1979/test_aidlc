I want you to modify the AI-DLC workflow in this project to introduce an explicit **Artifact Compaction / Intent Closure** step at the end of each completed workflow cycle.

### Objective

The current AI-DLC workflow generates a significant number of artifacts for every intent/workflow cycle. Over time, keeping all intermediate artifacts in the active `aidlc` tree creates:

* repository clutter;
* excessive context for LLMs;
* duplicated or contradictory information;
* difficulty identifying the current authoritative project knowledge;
* unnecessary growth of the active documentation surface.

I want to introduce a lifecycle where workflow artifacts are retained for traceability, but the **active project knowledge is compacted** after an intent is completed.

The key principle is:

> Historical workflow artifacts are evidence of what happened. Canonical project documents represent what is currently true.

Do NOT simply delete the artifacts.

---

## 1. Add a new final step: Artifact Compaction

After an intent has successfully completed its existing workflow phases (including verification), introduce:

```text
Artifact Compaction / Intent Closure
```

The overall lifecycle should become conceptually:

```text
Ideation
   ↓
Inception
   ↓
Construction
   ↓
Verification
   ↓
Artifact Compaction
   ↓
Intent Closed / Archived
```

The existing AI-DLC phases and behavior should remain unchanged unless modification is strictly necessary to introduce this lifecycle step.

---

## 2. Define what happens during compaction

The compaction step should analyze all artifacts generated by the completed intent and classify them into:

### A. Canonical project knowledge

Information that should survive as active project documentation, for example:

* architecture decisions;
* domain model changes;
* API/interface contracts;
* important requirements;
* NFR decisions;
* infrastructure decisions;
* important implementation constraints;
* durable design decisions;
* other information that is expected to remain valid for future workflows.

These should be consolidated into the project's canonical documentation/knowledge area.

Do not blindly copy every artifact.

If an existing canonical document already exists, update it rather than creating another duplicate document.

If a previous decision has been superseded, the canonical document should represent the latest valid state while retaining appropriate historical traceability.

---

### B. Workflow-specific artifacts

Examples:

* implementation plans;
* temporary analysis;
* intermediate design artifacts;
* generated planning documents;
* temporary checklists;
* intermediate AI artifacts;
* artifacts that were only useful during this intent.

These should NOT remain in the active project knowledge surface.

They should be moved to the intent archive.

---

### C. Audit/history information

Preserve enough information to reconstruct what happened during the intent.

The full audit trail should remain available, but it should not be part of the default active context used by future workflows.

---

## 3. Introduce an explicit archive

Create an appropriate archive structure, for example:

```text
aidlc/
  archive/
    <intent-id>/
      ...
```

or another structure consistent with the existing AI-DLC repository conventions.

The archive should contain the complete original intent artifacts needed for historical traceability.

Do not lose information simply because the intent has been compacted.

---

## 4. Introduce an intent summary

For every closed intent, create a concise summary such as:

```text
intent-summary.md
```

It should capture at least:

* intent name/id;
* objective;
* date;
* scope;
* units/workstreams involved;
* major requirements;
* major architecture/design decisions;
* important implementation decisions;
* important deviations from the original plan;
* validation/verification result;
* canonical documents updated;
* decisions superseded;
* links/references to the archived artifacts.

The summary should be small enough to be useful for future AI retrieval.

---

## 5. Establish canonical-vs-historical semantics

Introduce explicit conventions/documentation stating:

```text
Canonical project documentation
    = current authoritative state

Intent archive
    = historical record of what happened

Intent summary
    = compact historical/contextual representation

Audit
    = detailed traceability
```

Future AI-DLC workflows should preferentially use canonical project knowledge and the current intent.

They should retrieve historical intents only when historical context is actually relevant.

Do not make future workflows automatically ingest every archived intent.

---

## 6. Handle superseded information

This is important.

For example, if:

```text
Intent A:
API timeout = 30 seconds

Intent B:
API timeout = 60 seconds

Intent C:
API timeout = 90 seconds
```

the active canonical documentation should say:

```text
API timeout = 90 seconds
```

rather than exposing all three as equally authoritative.

However, the historical intents must still preserve the fact that previous values existed.

Use whatever existing ADR/decision/documentation mechanism the project already has. Do not introduce a parallel mechanism if an appropriate one already exists.

---

## 7. Add explicit workflow state

Extend the AI-DLC state model so that an intent has an explicit lifecycle such as:

```text
ACTIVE
   ↓
VERIFICATION_COMPLETE
   ↓
COMPACTION
   ↓
COMPACTED
   ↓
ARCHIVED / CLOSED
```

Use the project's existing state-machine conventions if available.

Do not invent a second independent state system.

The state should make it possible to determine programmatically:

* whether an intent has completed;
* whether compaction has happened;
* whether it has been archived;
* whether compaction failed or is incomplete.

---

## 8. Make compaction idempotent

This is a requirement.

If compaction is executed twice for the same intent, it must NOT create duplicate documentation or corrupt the canonical project knowledge.

For example:

```text
compact intent X
compact intent X again
```

should produce the same logical result as executing it once.

Use stable intent IDs and/or markers/versioning as appropriate.

---

## 9. Add a dry-run mode

If the existing CLI supports commands for workflow management, add something conceptually similar to:

```bash
aidlc intent compact <intent-id> --dry-run
```

The dry run should report:

```text
Canonical documents to create/update:
  - docs/architecture/payment-api.md
  - docs/decisions/ADR-031.md

Artifacts to archive:
  - inception/requirements.md
  - construction/unit-1/implementation-plan.md
  - ...

Artifacts to retain as history:
  - audit/...
  
Intent summary:
  - archive/260924-payment-api/intent-summary.md
```

No files should be modified during dry-run.

Adapt the command naming to the project's existing CLI conventions rather than introducing inconsistent terminology.

---

## 10. Add tests

Add automated tests covering at least:

1. A completed intent can be compacted successfully.
2. Canonical documentation is created when it does not exist.
3. Existing canonical documentation is updated rather than duplicated.
4. Superseded information is handled correctly.
5. Workflow-specific artifacts are archived.
6. Audit/history information remains available.
7. An intent summary is generated.
8. Running compaction twice is idempotent.
9. Dry-run does not modify files.
10. A failed compaction does not incorrectly mark the intent as closed.
11. Future workflows do not automatically ingest every archived artifact.
12. Existing AI-DLC workflows that do not use compaction continue to behave correctly.

## 13. Important design principle

Do not implement this as:

```text
workflow completed
        ↓
delete artifacts
```

Implement it as:

```text
workflow completed
        ↓
classify artifacts
        ↓
extract durable knowledge
        ↓
update canonical documentation
        ↓
generate compact intent summary
        ↓
preserve full historical artifacts
        ↓
archive intent
        ↓
mark intent CLOSED
```

The goal is to reduce the **active knowledge/context surface**, not to destroy history.

---
