# AI-DLC Intent Lifecycle

The project AI-DLC workflow is defined in `.agents/skills/aidlc-workflows/`. `aidlc-docs/current/aidlc-state.md` is the current intent state record; `aidlc-docs/current/audit.md` records active history. Closed intent summaries and full snapshots are stored in `aidlc-docs/archive/<intent-id>/`.

The workflow stages are defined in `.agents/skills/aidlc-workflows/SKILL.md`. After Build and Test, the Deploy stage prepares `aidlc-docs/current/deploy/pr_request.md` for every intent and `aidlc-docs/current/deploy/deploy_instructions.md` when ordered deployment or operational steps are needed. Deploy prepares documents only; it does not create a PR, execute notebooks, or deploy assets. Approval of the handoff is separate from authorization to execute deployment.

The lifecycle supports `ACTIVE`, `VERIFICATION_COMPLETE`, `VERIFICATION_WAIVED`, `COMPACTION`, `COMPACTION_FAILED`, `COMPACTED`, and `CLOSED`. `VERIFICATION_COMPLETE` requires successful Build and Test verification and approval. `VERIFICATION_WAIVED` requires explicit user acceptance of a documented limitation; it must never be reported as a passing result. A waiver does not authorize deployment.

After a passed result or accepted waiver and separate approval to close, prepare a curated manifest at `aidlc-docs/current/compaction/<intent-id>/manifest.json`. A waiver manifest uses `verification.status: waived`, `verification.user_accepted: true`, and details describing the unverified scope; the lifecycle state must record the same accepted waiver. Run a dry-run and review its archive, canonical updates, and cleanup list before applying.

Use `python3 scripts/aidlc_intent.py compact <intent-id> --dry-run` to preview and `python3 scripts/aidlc_intent.py compact <intent-id> --apply` to archive the complete listed history, apply curated canonical updates, clear workflow-only content from `aidlc-docs/current/`, and close the intent. Include approved Deploy handoff documents and the active manifest in the archive inventory before cleanup. The state and audit remain in `current/` with closure metadata and an archive pointer. Never put application source or configuration in cleanup paths.

For durable subproject design, maintain one application-design document at `aidlc-docs/knowledge/<project>/application-design.md` and one consolidated functional-design document per component at `aidlc-docs/knowledge/<project>/functional-design/<component>.md`. Keep working and approval artifacts in `current/`; curate updates from approved designs during compaction. Load the application design and only affected component designs when starting related work.
